# Cloudwright UX + Observability Audit

**Date:** 2026-05-01
**Version audited:** 1.2.2 (PyPI)
**Scope:** First-run UX, CLI surface, error messages, web UI first-impression, progressive disclosure, README, demo GIFs, onboarding friction; logging, LLM tracing, health checks, cost/token visibility, error reporting, debug mode, structured logs, metrics.

| Critical | Observability | No request correlation ID anywhere in the stack. Web requests, LLM calls, cost calls, validation calls, and SSE events share no common ID. ## Biggest unlocks

- **Wire request-correlation IDs through every LLM call, web request, SSE stream, and structured log line.** This single change moves the observability score from "log scrape" to "trace a user incident in 30 seconds" and unblocks every later metric/alert.
- **Split README into a 60-line QUICKSTART and a separate RELEASES/CHANGELOG.** First-run friction drops dramatically, PyPI long_description becomes scannable, and the 22-command help can be re-grouped at the same time. Both of these together likely double conversion from "saw the project" to "ran first design".
- **Fix per-model LLM pricing and emit token+cost in every API response (not just /api/chat).** Users currently see fictitious cost numbers for Haiku-routed modify calls; once accurate, surface them in the SummaryBar so cost awareness is constant. This also feeds into a Prometheus counter `cloudwright_llm_cost_usd_total{model=...}` for operators.
