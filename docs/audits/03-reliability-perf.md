## Scores

**Reliability: 64 / 100**

Strengths: retry logic with jitter exists for both providers, timeouts wrapped at the route level, rate limiter enforced on every router (visually verified across 8 routers — none missed), Pydantic v2 model validation on all inbound requests, path-traversal middleware, atomic ID validation in `SessionStore`. Failure-path tests exist (`test_rate_limiting`, `test_error_responses`, `test_llm_retry`). Test count is healthy.

Weaknesses dragging score down:
- Streaming reliability gaps (orphan threads, missing context manager in OpenAI, queue-full data loss).
- Non-atomic SessionStore writes; no fsync on auto-save.
- Cancellation semantics: route-level timeout doesn't cancel the SDK thread; LLM tokens still bill.
- `_extract_json` brace-counter is hand-rolled and has known edge cases (escape state, nested-JSON-strings).
- `_post_validate` writes Pydantic-invalid combos to specs (e.g. multi_az on bigquery).
- Frontend silently drops cost/validate failures, hiding errors from users.

**Performance: 67 / 100**

Strengths: catalog DB indexed and uses WAL; Anthropic prompt caching wired (even if partially-defeated by hint mutation); singletons cached behind double-checked locks; cost cache TTL'd and key-stable; templates pre-computed in memory; `asyncio.to_thread` used to keep event loop free.

Weaknesses:
- Anthropic prompt cache hit-rate near zero because `_build_system_with_hints` mutates the cached system prefix every turn (huge wasted opportunity — the system prompt is ~23 KB).
- OpenAI provider has no prompt-caching wiring.
- Catalog connection-per-call within a single estimate (~12 reconnects per spec).
- React UI has minimal memoization in `App.tsx` (zero useMemo/useCallback in 705 lines); large architectures will re-render aggressively.
- SSE responses don't disable proxy buffering (`X-Accel-Buffering: no`).
- `compare_providers` is serial.
- Rate limiter is per-worker (4× actual limit under default `multiprocessing.cpu_count()` workers).

## Three Unlocks

1. **Anthropic prompt caching surgery + OpenAI cache parity.** Split `CHAT_SYSTEM` (stable, 23 KB) from per-session hints/summary (variable). Keep `cache_control: ephemeral` only on the stable block. Cache hit on every follow-up turn = ~70-80% input-token savings on conversation flow + 200-400 ms first-token latency drop. Mirror with OpenAI's auto-cache by ensuring stable prefix is sent first. ROI: massive cost & latency win, ~1 day of work.

2. **Cancel-safe streaming.** Switch chat/stream to `anthropic.AsyncAnthropic` (and OpenAI's `AsyncClient`) so cancellation propagates natively without the worker-thread bridge. This kills three findings at once: orphan threads, queue-full data loss, and timeout-doesn't-cancel-LLM-bill. Bonus: removes the `threading.Thread` + `asyncio.Queue` bridge in `routers/chat.py` (~50 LOC simplification). ROI: reliability + cost; ~2 days.

3. **Atomic SessionStore + worker-shared rate limiter (Redis or single-worker).** `os.replace`-based atomic writes for sessions are 5 lines of code and eliminate corruption. Pinning to 1 uvicorn worker (or moving the rate limiter to Redis) makes the documented limit actually true. Both are required for any production single-tenant deploy. ROI: trust + correctness; <1 day.
